# Threat Model & Risk Assessment (Week 4)

## Core Rule
Treat all tool arguments coming from the model as untrusted input, exactly like a public web form.

## Tool Risk Mapping
1. **`list_documents` (Disk Access):**
   * *Threat:* Path Traversal.
   * *Risk:* If path validation is missing, it could read files outside the designated `data/` directory.

2. **`get_faq` & `search_notes` (Untrusted Strings & Data Processing):**
   * *Threat:* Untrusted Inputs & Runaway Responses.
   * *Risk:* Raw string queries from the model need strict validation (via Zod), and output sizes must be bounded to prevent exhausting the model's context window.



## Assets
* **Local Data Files:** Markdown notes (`architecture_notes.md`) and FAQ fixtures (`faq.json`) stored under `./data/`.
* **Filesystem Security:** The host machine's file system, which must remain strictly isolated from model instructions.
* **API/Network:** External or internal network interfaces (no active API tokens or secrets are stored in the repository).

## Trust Boundaries
* **Model ? Tool Arguments:** Raw query strings and parameters generated by the AI model entering the MCP tool execution layer.
* **Tool ? Filesystem:** Operations where tool code translates model inputs into local file path lookups or disk reads.
* **Tool ? Network:** Any outbound fetch or data-retrieval mechanisms interacting with external endpoints.

## Top 5 Risks
1. **Path Traversal in File Reading:** A model-controlled parameter could attempt to traverse directories using `../` to access files outside `./data/`.
2. **Missing Input Validation (Zod Schema Failures):** Passing malformed, unexpected, or undefined types to P0 tools (`search_notes`, `get_faq`) could cause unhandled exceptions.
3. **Runaway Responses / Large Context Flooding:** A broad search query could return an excessively large block of text, exhausting the model's context window.
4. **Server Crash via Unhandled Exceptions:** Runtime errors inside tool handlers crashing the entire MCP server instance instead of failing gracefully.
5. **SSRF (Server-Side Request Forgery):** If external data fetchers are unconstrained, a model-provided URL could target internal network resources.

## Mitigations This Week
* **Allowlist & Path Sanitization:** Enforce strict base-directory checks (`path.resolve` and `path.relative`) to ensure file reads stay contained inside `./data/`.
* **Zod Input Validation:** Rigorously validate all incoming tool arguments against strict Zod schemas before execution.
* **Output Size Capping:** Limit the maximum character length and snippet count returned by `search_notes` to prevent runaway responses.
* **Graceful Error Handling:** Wrap tool logic in try/catch blocks to return clean validation error messages rather than crashing the server.

## Out of Scope
* **Authentication and User Authorization:** Not implemented because this is a local student MCP server running in a trusted single-user environment.
* **Rate Limiting & Advanced Cryptography:** Excluded as the system does not handle multi-tenant user traffic or high-risk financial data.
